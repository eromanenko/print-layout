# План реалізації: Локалізатор Карт (Card Localizer)

Цей документ описує покроковий план створення інструменту для локалізації настільних карткових ігор, який буде інтегрований як окрема вкладка в існуючий застосунок `print-layout`.

## 1. Огляд та Мета

**Мета:** Додати нову вкладку "Локалізатор", де користувач зможе завантажити архів з картами, налаштувати текстові блоки (з підтримкою кількох мов та шрифтів), переглядати їх у режимі "галереї" та експортувати результат (конфіг та готові зображення).

**Основні технології:**
- **UI:** Vanilla JS, HTML, CSS (інтеграція в існуючу структуру вкладок).
- **Робота з файлами:** `JSZip` для читання та створення ZIP-архівів.
- **Рендеринг:** `Canvas API` для накладання тексту на зображення та генерації фінальних картинок.
- **Пам'ять:** Використання `URL.createObjectURL()` для "лінивого" завантаження зображень з пам'яті (щоб уникнути переповнення RAM).

---

## 2. Структура Конфігураційного Файлу (JSON)

Основою застосунку буде JSON-конфігурація, яка описує глобальні налаштування шрифтів та специфічні тексти для кожної карти.

```json
{
  "version": "1.0",
  "languages": ["en", "ua", "ru"],
  "fonts": {
    "TitleFont": { "family": "Arial", "size": 24, "color": "#000000", "weight": "bold" },
    "BodyFont": { "family": "Times New Roman", "size": 14, "color": "#333333", "weight": "normal" }
  },
  "cards": {
    "card_01.jpg": {
      "texts": [
        {
          "id": "block_1",
          "fontId": "TitleFont",
          "x": 10.5, "y": 5.0, "width": 80.0, "height": 15.0, 
          "align": "center",
          "content": {
            "en": "Fireball",
            "ua": "Вогняна Куля",
            "ru": "Огненный Шар"
          }
        },
        {
          "id": "block_2",
          "fontId": "BodyFont",
          "x": 10.5, "y": 50.0, "width": 80.0, "height": 40.0,
          "align": "left",
          "content": {
            "en": "Deals 5 damage.",
            "ua": "Завдає 5 одиниць шкоди.",
            "ru": "Наносит 5 урона."
          }
        }
      ]
    }
  }
}
```
> [!NOTE]
> Координати (`x`, `y`, `width`, `height`) будуть зберігатися у **відсотках** (0-100%) від ширини/висоти карти, щоб забезпечити незалежність від роздільної здатності завантажених зображень.

## 3. Етапи реалізації

Розробка буде розбита на 5 логічних фаз.

### Фаза 1: Базовий UI та Галерея (Робота з ZIP)
1. Додати HTML-структуру для нової вкладки ("Card Localizer") поруч з "Print Layout".
2. Створити інтерфейс: бічна панель (для завантаження файлів) та головна робоча область (Галерея).
3. Реалізувати читання ZIP-архіву з картинками через `JSZip` та множинне завантаження звичайних файлів-зображень.
4. Реалізувати "ліниве" створення URL для картинок та відображення їх по одній (кнопки "Вперед/Назад", розміщені над картою).
5. Додати кнопку "Rotate" (поворот за годинниковою стрілкою) для візуальної зручності при редагуванні альбомних карт (експорт відбуватиметься в оригінальній орієнтації).

### Фаза 2: Інтерфейс конфігурації (Мови та Шрифти)
1. Додати глобальний перемикач мов у бічну панель.
2. Створити менеджер "Стилів шрифтів" (додавання стилю, вибір системного шрифту або завантаження `.ttf` файлу, конвертація шрифту в `base64` для зручного збереження прямо в JSON).
3. Логіка імпорту/експорту базового JSON-конфігу.
4. Додати кнопку та модальне вікно для зручного перегляду JSON-конфігурації зі згортанням об'єктів та підсвічуванням синтаксису.

### Фаза 3: Редактор Тексту на Карті
1. Реалізувати накладання HTML-шару (`div` з `contenteditable` або `textarea`) поверх зображення карти у галереї.
2. Додати логіку створення нового текстового блоку (клік по карті -> створення блоку -> вибір стилю шрифту -> ввід тексту).
3. **UI Підказка (Tooltip):** Поруч з блоком тексту додати іконку "i", при наведенні на яку відображатиметься текст цього ж блоку іншими мовами (якщо він вже був введений).
4. Синхронізація введеного тексту з JSON-об'єктом для поточної карти та активної мови.
5. Перерахунок координат у відсотки при перетягуванні/зміні розміру блоку.

### Фаза 4: Рендеринг (Canvas) та Поведінка Тексту
1. Перенесення відображення тексту на HTML5 Canvas (потрібно для майбутнього експорту).
2. Реалізація **Word Wrap** (перенос по словах), якщо текст виходить за межі `width` блоку.
3. Логіка **Auto-shrink** (автоматичне зменшення шрифту), якщо текст не влазить по висоті `height`.
4. Реалізація вирівнювання тексту (left, center, right).

### Фаза 5: Експорт результатів
Додати в інтерфейс 4 варіанти збереження/експорту:
1. **Зберегти Проект (ZIP):** Архів, що містить оригінальні картинки та файл `config.json` (найзручніший спосіб для подальшого редагування).
2. **Зберегти Конфіг (JSON):** Завантажує лише файл `.json` (з вбудованими шрифтами).
3. **Експорт Зображень (ZIP):** Рендерить всі карти з текстами/затіркою і пакує готові зображення в архів.
4. **Експорт у PDF:** Пряма інтеграція з існуючим функціоналом `print-layout` для генерації готового до друку PDF-файлу з локалізованих карт.

### Фаза 6: Інструмент "Затірка" (Eraser Tool)
1. Додати інструмент для "замальовування" оригінального тексту.
2. Користувач малює прямокутник над оригінальним текстом і обирає колір затірки (можливо інструментом "піпетка", який бере колір з карти).
3. Ці блоки затірки (`x, y, width, height, color`) зберігаються в JSON конфігу для кожної карти. Вони рендеряться на Canvas під шаром з нашим новим текстом.

### Фаза 7: Додавання карт та реордерінг
1. Додавання окремих зображень до поточного списку `state.images` без втрати прогресу.
2. Створення міні-галереї або списку для візуального сортування карт перетягуванням.
3. Оновлення індексів у JSON конфігу при зміні порядку.

### Фаза 8: Імпорт текстів з таблиць (CSV/XLSX)
1.  **Підтримка форматів:** Реалізувати завантаження та парсинг файлів `.csv` та `.xlsx` (використання SheetJS).
2.  **Структура таблиці:**
    *   Перша колонка — назва файлу зображення (наприклад, `card_01.jpg`).
    *   Перший рядок (заголовки) — ідентифікатори мов (наприклад, `en`, `ua`, `ru`).
3.  **Інтерфейс імпорту (Modal):**
    *   Кнопка "Import" відкриває модальне вікно.
    *   В модальному вікні: коротка інструкція, посилання на завантаження прикладів (CSV/XLSX).
    *   Реалізація **Dropzone** (перетягування файлів) для завантаження.
4.  **Логіка імпорту:**
    *   Створення нових текстових блоків для відповідних карт.
    *   **Множинність:** Якщо для одного файлу є кілька рядків у таблиці — створюється кілька блоків.
    *   **Зміщення:** Блоки розміщуються з каскадним зміщенням (крок 2%), щоб їх можна було легко знайти.
    *   **Стилі:** Використовувати перший доступний стиль шрифту з конфігу.
    *   **Додавання:** Нові тексти додаються до вже існуючих.
5.  **Зміни в UI:**
    *   Перенести чекбокс "Autosave" у заголовок секції "Конфігурація (JSON)".

### Фаза 9: Відомі проблеми (Known Issues)
1. **Асиметричний ресайз та поворот на поверненій карті:** (Виправлено) Реалізовано через зміну точки прив'язки на (0,0) та коректний розрахунок якоря в екранних координатах.
2. Зробити інтерфейс JSON-в'юєра більш зручним. (Виконано)
3. **Вертикальне вирівнювання:** Текст у режимі редагування (HTML) знаходиться трохи нижче, ніж результат на Canvas (різниця в рендерингу baselines).

### Фаза 10: Оптимізація інтерфейсу
1. Поліпшити порядок пунктів меню, контроли, кнопки, кольори, іконки.

### Фаза 11: Конфігурація мов (Language Settings)
1. **Менеджер мов:** Додати UI для редагування списку підтримуваних мов (`languages` у JSON).
2. **Керування:** Можливість додавати нові мови та видаляти існуючі.
3. **Автоматизація:** Опція автоматичного додавання нових мов під час імпорту з таблиць (якщо в заголовку знайдено невідомий ID мови).

### Фаза 12: Зменшення складності коду ✅
1. Здійснено рефакторинг та видалено невикористані скрипти й стилі.
2. Файл `index.js` розбито на модулі: `state.js`, `renderer.js`, `overlays.js`, `ui.js`, `io.js`.
3. Перенесено inline-стилі з JavaScript у CSS-класи (`.loc-*`, `.is-active`).

### Фаза 13: Експорт текстів в CSV/XLSX

**Ціль:** Дати перекладачам можливість отримати всі тексти проекту у таблицю, відредагувати їх офлайн та імпортувати назад.

1. **Розширити модальний діалог:** Перейменувати поточне вікно «Import» на «Import / Export», додати вкладки або кнопки «Import» / «Export».
2. **Формат таблиці для експорту:**
   - `filename` — назва файлу карти
   - `font` — номер стилю шрифту (1, 2, …)
   - `x`, `y`, `width`, `height` — позиція блоку у відсотках
   - `rotation` — кут повороту (°)
   - По одному стовпцю на кожну мову (`en`, `uk`, …)
3. **Кнопки шаблонів:** «Export Table» поруч з «Download CSV Template» / «Download XLSX Template».
4. **Оновлений імпорт:** Якщо таблиця містить стовпці позиції (`x`, `y`, `width`, `height`, `rotation`) — оновлювати координати блоків.
5. **Режим імпорту (чекбокс «Replace existing texts»):**
   - **Увімкнено:** Усі існуючі текстові блоки карти видаляються перед додаванням нових (таблиця — «джерело правди»).
   - **Вимкнено:** Нові тексти додаються поверх існуючих (поточна поведінка).

### Фаза 14: Інструменти видалення оригінального тексту

**Ціль:** Доповнити патч-інструмент засобами, які краще приховують оригінальний текст.

1. ✅ **Content-aware fill (розмиття):** Розмити ділянку під патчем (Gaussian blur на `canvas`) замість суцільного кольору.
2. ✅ **Clone stamp:** Копіювання текстури сусіднього регіону для маскування тексту. З рухомим джерелом клонування.
3. ✅ **Патч-режими:** Вибір режиму заливки для кожного патча — `Solid color` / `Blur` / `Clone` / `Smart Erase`.
4. 🛠️ **Smart Erase (Inpaint):** Розумне видалення тексту за допомогою OpenCV.js. (Потребує доопрацювання)
   - **Як працює алгоритм:** 
     1. OpenCV.js завантажується динамічно (lazy-load) з CDN лише при першому виборі режиму `Smart Erase`.
     2. Вирізається ROI (регіон інтересу) навколо патча з невеликим відступом.
     3. Зображення конвертується з RGBA в **RGB** (алгоритм `cv.inpaint` не підтримує 4-канальні зображення).
     4. Шукаються контури тексту за допомогою `cv.Canny` (чутливість регулюється повзунком).
     5. Контури розширюються через `cv.dilate` за допомогою `cv.getStructuringElement` (товщина регулюється повзунком), щоб захопити напівпрозорі краї літер.
     6. Маска перетинається з формою самого патча (щоб не видаляти текст поза межами патча).
     7. Виконується `cv.inpaint` (алгоритм TELEA) для реконструкції фону і результат кешується.
   - **Уникнення минулих помилок (граблі):**
     - **Помилка з `cv.inpaint`:** Функція `cv.inpaint` в OpenCV.js жорстко вимагає `CV_8UC1` або `CV_8UC3` (RGB). Передача RGBA зображення з Canvas призводить до помилки (що раніше проявлялося як безкінечне показування заглушки-розмиття). Обов'язково конвертувати в `cv.COLOR_RGBA2RGB`.
     - **Помилка з геометрією OpenCV:** Спроба намалювати полігон (повернутий патч) через `cv.RotatedRect` та `cv.fillPoly` з передачею `cv.MatVector` в JS є дуже нестабільною і часто викидає винятки через проблеми з JS-біндінгами масивів (`push` замість `push_back` та розмірності матриць точок).
     - **Правильне рішення для маски:** Використовувати нативний HTML5 Canvas API (`getContext('2d')`, `rotate`, `fillRect`, `getImageData`) для створення чорно-білої маски патча, а потім просто завантажувати ці пікселі в `cv.Mat`. Це 100% надійно.
     - **Тихі помилки:** OpenCV помилки в JS не завжди зупиняють виконання очевидно, тому важливо обгортати їх у `try-catch` з логуванням.
